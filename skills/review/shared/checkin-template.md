# Check-in screen template

Every check-in, from the core or from a pack, uses this shape, delivered with ASK (see your platform reference). The user can always type a free answer. Screens also follow the voice rules in SKILL.md ("What the chat shows"): first person and plain words, with no agent, gate, or verdict names.

## Rounds, not interrogations

These rules follow the Grill Me method.

- **Facts are the tool's job. Decisions are the user's.** Never ask the user anything the paper or an outside source can settle. DISPATCH an agent to find it. Only judgment calls reach the user.
- **Ask a round.** Stages 3 and 4 write their questions to `{WORKSPACE}/stage-N/questions.json`: a JSON list of objects with `id` (the item id), `stop`, `text`, `options` (full labels, recommended first), `recommended` (the full recommended label), `depends_on` (a list of item ids that must be answered first), and `prune_if` (an object mapping an item id to an answer letter; if that item was answered with that letter, the question is dropped). Run `plumb frontier {WORKSPACE}/stage-N/questions.json {WORKSPACE}` and ask every question it returns in one round. Batch four per screen where the platform allows.
- **Answers reshape the tree.** After recording the round, run `frontier` again. Questions unblocked by the answers form the next round. Questions pruned by an answer are never asked. Repeat until `frontier` returns an empty list. That is the exit condition for the stop. At a level that skips the stop, record the recommended option for each question `frontier` returns, with `--note auto`, and run it again until it is empty.
- **Paste content before asking.** When a check-in presents content, meaning a summary, issue cards, disagreeing table cells, flags, or rulings, first paste the full text of that content into the chat as a normal message. Only then ASK the question. Never rely on the question box or a file name to show it.
- **Every question carries a recommended answer**, listed first. The exception is a pure preference, such as whose paper it is or which journal: list its options without "(Recommended)" and record it with an empty recommendation and `--note preference`. No override is logged for it.

1. One sentence saying what the tool just did. Example: "I checked your identification strategy against the setting."
2. The finding in plain words. No agent names, file names, or pipeline terms. Cite a page or table.
3. Options with letters in the label (A., B., C., D.). Put the recommended option first and end its label with "(Recommended)".
4. The question's `header` field shows the stage and the time left, for example "Diagnose ~12m".

Before asking, check `plumb answered {WORKSPACE}`. Skip any (stop, item) pair already there. For items numbered by an agent, run the text replay below first.

## Items numbered by an agent: record and replay by text

An agent numbers the alternatives (`against:<n>`) and the major issues (`majors:<n>`). When a stage reruns, the agent may number them differently, so an answer is tied to the item's text, not only its number. Minors follow the same idea in Stage 5.

- The question's `text` starts with the item's first sentence, copied word for word from the file that numbers it.
- Record both labels with ` | ` and that sentence appended: `plumb checkin {WORKSPACE} <stop> <item> "<recommended label> | <first sentence>" "<chosen label> | <first sentence>"`. `frontier` and `prune_if` read only the letter at the start of the label, so pruning still works.
- Replay, when the stage reruns: after writing `questions.json` and before the first `frontier`, read `plumb answered {WORKSPACE} --labels`. For each question, look for a recorded answer to an item with the same prefix (`against:` or `majors:`) whose text after ` | ` is clearly the question's first sentence. If one matches and it is not already the last answer under the question's id, record it again under the question's id, with `--note "replayed; <original note>"` (the original note is on that answer's `checkin` event in `{WORKSPACE}/audit/events.jsonl`). If none clearly matches but the question's id already has an answer (about another item), change the question's `id` in `questions.json` to `<id>:r`, or, if `<id>:r` already has an answer, to `<id>:r2`, `<id>:r3`, and so on, taking the first with no answer, so `frontier` asks it again. Record that answer under that suffixed id. Then copy it under `<id>`, so `depends_on`, `prune_if`, and later stages that read `<id>` see it, marking the copy as a replay so it is not counted twice: `plumb checkin {WORKSPACE} <stop> <id> "<recommended label> | <first sentence>" "<chosen label> | <first sentence>" --note "replayed; <original note>"`. A question whose id has no answer is asked as usual.
- The page lines in `{WORKSPACE}/stage-6/advocate_pages.md` carry item numbers too. At the start of the replay, remove this stop's lines from that file. For each replayed answer that asked for a page (B at `against`, C at `majors`), write its line again under the question's current id, from the page and claim in its original note.

After the final answer, record it once: `plumb checkin {WORKSPACE} <stop> <item> "<recommended label>" "<chosen label>"`. If the answer has a follow-up (a page and claim, a correction), ask the follow-up first and put its text in this record's `--note`; if the question is asked again (dig deeper, the re-ask below, draft edits), record only the last answer. Override counts read the last answer recorded for each item, so a second record never counts twice, but record once all the same. At a stop the level does not ask, record the recommended option as the answer with `--note auto`: `plumb checkin {WORKSPACE} <stop> <item> "<recommended label>" "<recommended label>" --note auto`. The user wins every disagreement. An answer counts as overruling the tool only at the numbers, read, against, majors, minors, and draft stops, only when the question had a recommended option, and only when the chosen option differs from it. Setup answers, delegations (`--note "delegated to the tool"`), replays (`--note "replayed; ..."`), answers the tool took at a skipped stop (`--note auto`, reported apart as `auto_answers` by `plumb counts`), and typed answers never count. Record a typed answer that matches none of the options with `plumb checkin {WORKSPACE} <stop> <item> "<recommended label>" "<typed answer>" --note "free text"`. In author mode, before dropping a point the tool recommended keeping, first show one line with the reason referees raise it, then ask again with "Drop it" and "Keep it". Record only the final answer, as the original question's option: "Keep it" as the original recommended label, and "Drop it" as the original option that drops the point, which is the one the user first chose (at minors, "Drop: <first sentence>").

At any screen, if the user types "fewer questions", switch the level for the rest of the run (standard to light, handson to standard). Update `run.json` and record it as a check-in: `plumb checkin {WORKSPACE} setup setup:level_change "" "<new level label>" --note preference`, with the new level's label as the `setup:level` question gives it, without "(Recommended)": "B. Light" or "A. Standard".
