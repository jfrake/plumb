3. Then dispatch `agents/theory-devil.md` with `REVISIONS=<revisions>` and `REVIEW=1`, and pass it the `stage-3/` paths the step 2 agents named, as its pack theory reports (none if there are none). It reads the Stage 3 outputs from steps 1-2 and writes `{WORKSPACE}/stage-3/theory_devil_report.md` and `{WORKSPACE}/stage-3/alternatives.md`, with the 3-4 strongest alternative explanations, each naming a theory or paper.

4. Verdict gate, read from `theory_devil_report.md`. Report the result in chat by the voice rules in SKILL.md, never the verdict word or the agent name.
   - Go: continue to step 5.
   - Revise: re-dispatch each flagged agent, core or pack, by the name the report gives, with "Read `{WORKSPACE}/stage-3/theory_devil_report.md` for the changes required", then re-run `agents/theory-devil.md` with `REVISIONS=<revisions>`, the next `REVIEW` number, and the same pack theory reports. A re-dispatched pack agent rewrites every file it wrote. Allow up to `revisions` revision cycles (`limits.revisions` in `run.json`).
   - Rethink, or a Revise verdict after the last allowed revision: ASK the user with the flagged concerns (paste into the chat first; see the check-in template), in one or two plain sentences. Options: "A. Proceed, keep the concerns on record (Recommended)", "B. Stop the review". Record with `plumb checkin {WORKSPACE} against against:devil_gate "<recommended label>" "<chosen label>"`. At levels where the `against` stop is not asked (light, auto; see `stops_for` in `plumb/checkin.py`), take A and record it the same way with `--note auto` (a skipped stop's answer is never an override).

5. "What is this paper arguing against?" Write `{WORKSPACE}/stage-3/questions.json` (schema in `shared/checkin-template.md`) with one question per alternative in `alternatives.md`, item id `against:<n>` (n = the alternative's number), stop `against`, empty `depends_on` and `prune_if`. Options:
   - "A. Plausible, investigate further (Recommended)"
   - "B. Plausible, but the paper handles it (give the page)"
   - "C. Not plausible here"
   - "D. Let the tool decide"

   Show the context before asking (see the check-in template). Before the first round, paste the paper's explanation section from `alternatives.md` into the chat once. Before each alternative's question, paste that alternative's section in full: its heading sentence, how it would produce the results, which results it could explain, and what would tell them apart. Do not shorten or summarize it.

   The alternatives are numbered by an agent, so record and replay them by text as `shared/checkin-template.md` says ("Items numbered by an agent"). Ask the rounds that `plumb frontier {WORKSPACE}/stage-3/questions.json {WORKSPACE}` returns, and record each final answer once with `plumb checkin {WORKSPACE} against against:<n> "<recommended label> | <first sentence>" "<chosen label> | <first sentence>"`. Alternatives marked C are dropped from later stages, and Stage 4 prunes the major issues that rest on them. D means the user delegates the call to the tool, which is not an override: the alternative is investigated further, as for A. Record a D answer as the recommended label: `plumb checkin {WORKSPACE} against against:<n> "<recommended label> | <first sentence>" "<recommended label> | <first sentence>" --note "delegated to the tool"`. No override is logged, and the note keeps the delegation on record. Alternatives marked B go to Stage 6's advocate for a check against the page. After a B, and before recording it, ASK a free-text follow-up: "Which page, and what does the paper say there?" Create `{WORKSPACE}/stage-6/` if it does not exist yet, and append a line to `{WORKSPACE}/stage-6/advocate_pages.md` in the form `against:<n>: p.<page> — <one-line claim>`, using the page and claim the user gave. Then record the B answer once, with the reply as its note: `plumb checkin {WORKSPACE} against against:<n> "<recommended label> | <first sentence>" "<chosen label> | <first sentence>" --note "p.<page>: <one-line claim>"`. Do not record the B a second time without the note. At levels where the `against` stop is not asked (light, auto), take A for every alternative and record it the same way with `--note auto`, so Stage 4's cards that depend on these answers are not blocked.
