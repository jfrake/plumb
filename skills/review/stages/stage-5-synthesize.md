# Stage 5: Synthesize

1. Construction-claim audit. If `construction-claim-audit.md` is under `run.json` `core_adjust` `off` (a pack turned the ledger off), do not dispatch it. Log `plumb log {WORKSPACE} verification '{"check":"construction_claim_audit","verdict":"NOT RUN"}'` and continue to step 2 as for CLEAN. Otherwise dispatch `agents/construction-claim-audit.md`. It checks the construction claims in the Stage 2-4 files against `{WORKSPACE}/stage-2/construction_ledger.json` and writes `{WORKSPACE}/stage-5/construction_claim_audit.md`. Read the `Verdict:` line in its `## Summary` and log it: `plumb log {WORKSPACE} verification '{"check":"construction_claim_audit","verdict":"<verdict>"}'`.
   - CLEAN: continue to step 2.
   - INFERENCES FLAGGED only: continue to step 2. Pass the audit to the synthesis agent, which must drop each UNGROUNDED-INFERENCE or ground it with a ledger citation.
   - CONTRADICTIONS FOUND (with or without inferences flagged): re-dispatch the agent that wrote each flagged file, with "Read `{WORKSPACE}/stage-5/construction_claim_audit.md` and correct the contradictions it lists in your output." Then re-run the audit. Allow up to `revisions` correction cycles (`limits.revisions` in `run.json`). If contradictions persist after the last one, go to the check-in below.

<!-- CHECKIN: majors -->
   Unresolved contradictions: ASK, in one or two plain sentences, what the paper's own description of the variables contradicts (paste into the chat first; see the check-in template). Options: "A. Keep going, and list them as limitations (Recommended)", "B. Stop the review". Record with `plumb checkin {WORKSPACE} majors majors:construction_audit "<recommended label>" "<chosen label>"`. At levels where the `majors` stop is not asked (see `stops_for` in `plumb/checkin.py`), take A and record it the same way with `--note auto` (a skipped stop's answer is never an override). For A, pass the audit to the synthesis agent with the instruction to surface each unresolved contradiction as a limitation.

2. Dispatch `agents/synthesis.md` with the kept majors, the user's answers (including the `against:<n>` answers, so findings on an alternative marked "C. Not plausible here" are excluded as `user_ruled_out: against:<n>`), the profile norms, `shared/proportion-and-concision.md`, `stage-1/reference_list.md` if it exists (a listed work that was not found, or whose authors or year do not match, may be raised as a minor issue with the entry quoted), and `stage-1/flags.json` if it exists (an issue built on one of its flags names the flag's `item` in its `sources`). It writes `stage-5/issues.json`, `synthesis_coverage.md`, `stage-5/held_minors.md`, and the draft at `stage-5/draft.md`, always in issues-list format, whatever outputs were chosen.
3. Run `python3 {PLUGIN}/skills/review/scripts/audit_coverage.py {WORKSPACE} <paper_dir>`, where `<paper_dir>` is the folder that holds the PDF (the script reads only `{WORKSPACE}`). HARD gate. If it fails, send the audit messages back to `agents/synthesis.md` and run the audit again, up to `revisions` times. Each time step 3 runs, including from the critic loop in step 4, it starts a new count. If it still fails, stop and show the messages.
4. Synthesis critic. Dispatch `agents/synthesis-critic.md`. It writes `{WORKSPACE}/stage-5/synthesis_critic_report.md` and replies with `VERDICT: CLEAN` or `VERDICT: REVISE`. Report the result in chat by the voice rules in SKILL.md, never the verdict word or the agent name.
   - CLEAN: continue to step 5.
   - REVISE: re-dispatch `agents/synthesis.md` with "Read `{WORKSPACE}/stage-5/synthesis_critic_report.md` and fix each flag it lists." Re-run step 3, then re-run the critic. Allow up to `revisions` synthesis revisions. If the verdict after the last one is still REVISE, go to the check-in below.

<!-- CHECKIN: majors -->
   Critic still flags problems after the last allowed revision: ASK, in one or two plain sentences, what the draft still gets wrong (paste into the chat first; see the check-in template). Options: "A. Keep the draft, and note the flags (Recommended)", "B. Stop the review". Record with `plumb checkin {WORKSPACE} majors majors:synthesis_critic "<recommended label>" "<chosen label>"`. At levels where the `majors` stop is not asked, take A and record it the same way with `--note auto`. For A, append the unresolved flags to `brief.md`.

<!-- CHECKIN: minors -->
5. Minor issues. If `minors_mode` is "list", show `held_minors.md` (paste into the chat first; see the check-in template) as one question with "A. Keep all (Recommended)", "B. Keep only the first three", and "C. Let me pick", item id `minors:list`. If "each", ask one question per minor (paste into the chat first; see the check-in template) with "Keep" and "Drop", item id `minors:<n>`. `minors_mode` is in `plumb/checkin.py`: "list" at standard, "each" at handson. At levels where the `minors` stop is not asked, take A under `minors:list` and record it the same way with `--note auto`. Record the answers with `plumb checkin {WORKSPACE} minors <item> "<recommended label>" "<chosen label>"` and regenerate the draft's closing minor comment. Record a dropped minor, in "each" mode and for "C. Let me pick," as `minors:<n>` with the answer `"Drop: <the minor's first sentence>"`, so the choice can be replayed by its text; synthesis may renumber the minors when it reruns. Its recommended label is "Keep (Recommended)" in both cases, so each dropped minor counts as one override; "C. Let me pick" itself is not an override. Under "C. Let me pick", also record each kept minor, so every minor shown is one answer: `plumb checkin {WORKSPACE} minors minors:<n> "Keep (Recommended)" "Keep (Recommended)"`.

   Resume. If this stage runs again after a stopped run, synthesis rewrites `held_minors.md` and the draft with every minor restored, and the answered minors questions are not asked again. Read the recorded answers with `plumb answered {WORKSPACE} --labels` (the last answer for each item wins; the same answers are the `checkin` events in `{WORKSPACE}/audit/events.jsonl`) and apply them to the new draft: for `minors:list` answer B, keep only the first three; for each `minors:<n>` answer that starts with "Drop:", drop the regenerated minor whose text matches the recorded sentence, whatever its number now. If no minor clearly matches, ask about that minor again under the item id `minors:<n>:r`, or, if that already has an answer, `minors:<n>:r2`, `minors:<n>:r3`, and so on, taking the first with no answer. Then regenerate the closing minor comment. Ask only the minors questions that have no recorded answer.

6. Check the issue file. Run `plumb check-issues {WORKSPACE}/stage-5/issues.json --draft {WORKSPACE}/stage-5/draft.md`. It prints OK when the file exists, parses, and is a list of issues that each have an `id`, `kind`, `summary`, and `checkin`. On exit 2, re-dispatch `agents/synthesis.md` with the message and "Rewrite `{WORKSPACE}/stage-5/issues.json` in the format given; change nothing else." On exit 1, an issue's `title`, `summary`, `why`, or `settle`, or the draft, uses a metaphor, and the writers would copy it word for word; re-dispatch `agents/synthesis.md` with the message and "Reword each listed field or draft passage without metaphors, and make the same change wherever that text appears in `{WORKSPACE}/stage-5/issues.json` and `{WORKSPACE}/stage-5/draft.md`. Change no fact, number, or page; replace only the metaphor." Check again, up to `revisions` times. If it still fails, show the message and stop. Then run `plumb check-minors {WORKSPACE}`. It prints OK when every minor the user kept at step 5 is in `{WORKSPACE}/stage-5/draft.md`, its line starting with its `summary` word for word. On exit 1, re-dispatch `agents/synthesis.md` with the message and "Put each listed minor in the draft's `## Minor issues` list, its line starting with its `summary` from `{WORKSPACE}/stage-5/issues.json` word for word; change nothing else." Check again, up to `revisions` times. If it still fails, show the message and stop. Exit 2 means an input is missing or malformed: show the message and stop.
