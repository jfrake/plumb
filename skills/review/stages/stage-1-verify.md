# Stage 1: Verify

Everything here is settled by the paper or an outside source.

1. If table pages were rendered: for each entry in `{WORKSPACE}/table_pages/index.json`, PARALLEL two independent DISPATCHes of `agents/table-transcriber.md`, one writing to `{WORKSPACE}/transcriptions/a/`, the other to `{WORKSPACE}/transcriptions/b/`. Each entry is one table; pass the transcriber every image in its `images` list (a table continued across pages has several). Neither sees the other's output or the page text. Each also writes the table's title and note, word for word, as `table_NN_note.txt`. If a transcriber reports that a table continues on a page not in its entry, add that page with `python3 {PLUGIN}/skills/review/scripts/render_table_pages.py <pdf> {WORKSPACE}/table_pages --pages <n> --table <label>`, delete that table's CSV from both transcription folders, and dispatch the pair again for the entry. Then run `python3 {PLUGIN}/skills/review/scripts/compare_transcriptions.py {WORKSPACE}/transcriptions/a {WORKSPACE}/transcriptions/b {WORKSPACE}/extracted_tables`. It writes the agreed tables (disagreeing cells blanked), each agreed note beside its table, and `disagreements.json`. Two notes that differ are recorded there with reason `note`; no note is written for that table, so its star check is skipped. An entry with `whole_table: true` (reason `shape`, `missing_in_a`, or `missing_in_b`) means the two readings could not be lined up, so no agreed table was written. The script also prints each one. Never drop such a table quietly: log `plumb log {WORKSPACE} dependency '{"name":"table:<table>","message":"the two readings disagree on the whole table (<reason>); not verified"}'` and take it to the check-in below. Log one verification event per table with the number of disagreeing cells. Log a table that took a transcriber unusually long, or that it marked hard to read, as a verification event with `note: "hard to read"`.
2. `python3 {PLUGIN}/skills/review/scripts/verify_arithmetic.py {WORKSPACE}/extracted_tables {WORKSPACE}/stage-1/arithmetic.md`. Report-only. Log each flag as a verification event with `adjudication: paper`. The script also checks each significance mark against its coefficient and standard error, reading the key to the marks and what the parentheses hold from the table's note; it flags only a mark that claims more significance than the printed numbers allow, and a note it cannot read is listed as not computable, never guessed. Log how many tables it skipped (`skipped` counts tables, not the per-cell lines for one table): `plumb log {WORKSPACE} verification '{"check":"stars_vs_se","skipped":<n>,"report":"stage-1/arithmetic.md"}'`.
3. In parallel: dispatch `agents/numeric-fidelity.md`, which writes `{WORKSPACE}/stage-1/numeric_fidelity.md`, comparing numbers in the text with the tables; and build the hypothesis ledger. If `fingerprint.md` says `Hypotheses: none`, run `python3 {PLUGIN}/skills/review/scripts/verify_hypothesis_ledger.py --skip {WORKSPACE}/stage-1/hypothesis_ledger.json "the fingerprint lists no hypotheses"` and log `plumb log {WORKSPACE} verification '{"check":"hypothesis_ledger","verdict":"SKIPPED"}'`; nothing below in this step runs, and no hypothesis question is asked. Otherwise dispatch `agents/hypothesis-ledger-producer.md`.
   - At Standard and Deep, dispatch `agents/hypothesis-ledger-checker.md`, then run `python3 {PLUGIN}/skills/review/scripts/verify_hypothesis_ledger.py {WORKSPACE}/stage-1/hypothesis_ledger.json {WORKSPACE}/stage-1/hypothesis_ledger_gate.md`.
   - At Quick, run the gate with `--allow-unverified`, run the script below, and when `stage-1/hypothesis_checks.md` lists flags or the ledger has rows with no test, dispatch `agents/hypothesis-ledger-checker.md` with "Re-derive only these rows: <ids>"; then run the gate without the option and the script again. When the checker is not dispatched, the `--allow-unverified` pass is final: the ledger stays unsigned, the producer's "Hypotheses and their tests" block stands, and the gate and the script are not run again. On this path too, `check_hypotheses.py` exits 2 when it cannot read the ledger or an import fails; then it wrote no report: record it under the check-in's not-computed list as "hypothesis checks did not run", and do not stop the review.
   - On gate exit 1 or 2, dispatch `agents/hypothesis-ledger-checker.md` once more with the gate report and rerun the gate. If it still fails, rename the ledger to `{WORKSPACE}/stage-1/hypothesis_ledger.failed.json` and the readable copy to `{WORKSPACE}/stage-1/hypothesis_ledger.failed.md`, so later stages do not show the failed mapping, log `plumb log {WORKSPACE} dependency '{"name":"hypothesis_ledger","message":"ledger failed its gate twice; hypothesis checks did not run"}'`, and skip the script, the mapping check, and Stage 4's hypothesis audit.
   - On exit 0, log each line under `## Advisory` in the gate report as `plumb log {WORKSPACE} verification '{"check":"hypothesis_ledger_advisory","detail":"<line>"}'`, run `python3 {PLUGIN}/skills/review/scripts/check_hypotheses.py {WORKSPACE}/stage-1/hypothesis_ledger.json {WORKSPACE}/stage-1/hypothesis_checks.md --json {WORKSPACE}/stage-1/hypothesis_checks.json`, and log `plumb log {WORKSPACE} verification '{"check":"hypothesis_checks","flags":<n>,"report":"stage-1/hypothesis_checks.md"}'`. `check_hypotheses.py` exits 2 when it cannot read the ledger or an import fails; then it wrote no report: record it under the check-in's not-computed list as "hypothesis checks did not run", and do not stop the review.
4. For each pack listed in `run.json` `packs`, run its `verify` slot agents. A pack's scripts are run by its own verify agent; the orchestrator runs none. Run no other pack's agents. A pack's verify agent writes `{WORKSPACE}/stage-1/<pack>_numbers.md`, with its problems as a numbered list under `## Flags`.

5. Number flags, in two rounds. Record every answer with `plumb checkin {WORKSPACE} numbers <item> "<recommended label>" "<chosen label>"`.
   - Before round 1, write `{WORKSPACE}/stage-1/flags.json`: a JSON list with one record per question in both rounds, in the order asked. Each record has `id` (its number in that order, as a string), `item` (its item id below), `kind` (`cell`, `table`, or `number`), `title` (one short line), `severity` (null), `summary` (the one or two plain sentences the screen shows), `excerpt` (for a text-table flag, the sentence from the paper that it quotes, copied word for word; otherwise null), `ms_page` (the page the paper prints, when the flag gives one; otherwise null), `pdf_page` (for a cell, a table, or an arithmetic flag, the `page` of its table in `{WORKSPACE}/table_pages/index.json`; otherwise null), `table` (the table's label, or null), and `cells` (the `<table>:<row>:<col>` of each cell the flag rests on, or an empty list).
   - Page offset, once per run and at every level, whether or not the `numbers` stop is asked. RUN `python3 {PLUGIN}/skills/review/scripts/locate_issues.py --page-offset <pdf>`. It prints the paper's page offset (the PDF page minus the page the paper prints, seen on at least two pages) as an integer, or `null`. For an integer n, run `plumb page-offset {WORKSPACE} <n>`, which writes `page_offset` into `run.json`. When it prints `null`, write nothing.
   - Where the `numbers` stop is asked, pin these items to a working copy of the paper. RUN `python3 {PLUGIN}/skills/review/scripts/locate_issues.py <pdf> {WORKSPACE}/stage-1/flags.json {WORKSPACE}/stage-1/flags_locations.json`, then `python3 {PLUGIN}/skills/review/scripts/annotate_pdf.py <pdf> {WORKSPACE}/stage-1/flags.json {WORKSPACE}/stage-1/flags_locations.json {WORKSPACE}/checkin_numbers_annotated.pdf`. Start the first screen with "Open {WORKSPACE}/checkin_numbers_annotated.pdf to see each flag on its page." If step 2 runs again after round 1, rewrite the `number` records and make the copy again before round 2. Where the stop is not asked, write `flags.json` but make no copy.
   - Round 1, the transcription disagreements in `disagreements.json`. Show the page image path with each. Entries with reason `note` are not asked and have no record in `flags.json`. Entries with reason `header_rows` are not asked either: the comparison set aside a heading row that only one reading kept, and the rest of the table was compared cell by cell.
     - Each cell: show both readings (paste into the chat first; see the check-in template). Item id `numbers:cell:<table>:<row>:<col>`. Options: "A. Leave it blank and list it as unverified (Recommended)", "B. Reading 1", "C. Reading 2", "D. Neither (type the value)". For B, C, or D, write the value into the agreed table, and record the chosen label with the value appended, for example "B. Reading 1: 0.26**" or "D. Neither: 0.31", so a rerun can apply it again.
     - Each whole-table entry: show both CSVs (`a_file`, `b_file`; one may be absent) (paste into the chat first; see the check-in template). Item id `numbers:table:<table>`. Options: "A. Leave the table unverified and list it (Recommended)", "B. Use reading 1", "C. Use reading 2". Offer only the readings that exist. For B or C, copy that CSV into `{WORKSPACE}/extracted_tables/`.
     - If any value or table was written, re-run `verify_arithmetic.py` from step 2. Then DISPATCH again the `verify` slot agent of each pack in `run.json` `packs` whose `stage-1/<pack>_numbers.md` lists under `## Not computed` a written cell or a cell of a table copied in at round 1, and use its new flags, before round 2. Also DISPATCH `agents/hypothesis-ledger-checker.md` again when `stage-1/hypothesis_checks.md` lists under `## Not computed` a written cell or a cell of a table copied in at round 1, with "Fill the estimates whose cells were written at the check-in; change nothing else."; then rerun the gate and the script as in step 3, and use the new flags, before round 2.
   - Round 2 starts with the mapping check, when `stage-1/hypothesis_ledger.json` exists and has rows. Paste the block "Hypotheses and their tests" from `{WORKSPACE}/stage-1/hypothesis_ledger.md` into the chat (see the check-in template), then ask. Item id `numbers:hyp:mapping`. Options: "A. The mapping is right (Recommended)", "B. Correct a line". On B, ASK for the correction as free text, dispatch `agents/hypothesis-ledger-checker.md` with it, rerun the gate and the script as in step 3, rewrite the `numbers:hyp:` records in `flags.json` from the new `hypothesis_checks.md`, and make the working copy again where one is made. Record the answer once, with the correction as its note: `plumb checkin {WORKSPACE} numbers numbers:hyp:mapping "A. The mapping is right (Recommended)" "<chosen label>" --note "<the correction>"`. The mapping check has no record in `flags.json`. Where the `numbers` stop is not asked, take A and record it with `--note auto`.
   - Round 2, each discrepancy in `arithmetic.md` and `numeric_fidelity.md` (paste into the chat first; see the check-in template). Item id `numbers:arith:<table>:<cell>:<check>` for an arithmetic flag, `numbers:text:<n>` for a text-table flag (n = its number in `numeric_fidelity.md`). Also ask each item under `## Flags` in every `stage-1/<pack>_numbers.md` for a pack in `run.json` `packs`, item id `numbers:pack:<pack>:<n>` (n = its number in that list), kind `number` in `flags.json`. When a pack flag's line ends with `Table:` and `Cells:`, copy them into the record's `table` and `cells`. Also ask each item under `## Flags` in `stage-1/hypothesis_checks.md`, item id `numbers:hyp:<hypothesis id>:<check>` as its line gives it (for example `numbers:hyp:H2:HL3`), kind `number` in `flags.json`, with `table` and `cells` from the line's `Table:` and `Cells:`; its options are "A. Real problem in the paper (Recommended)" and "B. The ledger misread the paper". Options: "A. Real problem in the paper (Recommended)", "B. Extraction error"; for a `numbers:pack:*` item, "B. Not a problem or misread"; for a `numbers:hyp:*` item, "B. The ledger misread the paper". Items answered B are dropped and logged. For a `stars_vs_se` flag that `numeric_fidelity.md` Part C rates BENIGN MISMATCH (the paper states one-tailed tests, or takes its marks from another method), offer a third option and recommend it instead: "A. Real problem in the paper", "B. Extraction error", "C. The paper states one-tailed tests or another source for the marks (Recommended)". Items answered C are dropped and logged the same way. Write `{WORKSPACE}/stage-1/dropped_flags.md`: one line per dropped item, in the form "- `<item id>`", or "None." when nothing was dropped. Pack diagnose agents read it.
   - Write every cell and table still marked A in round 1 to `{WORKSPACE}/stage-1/unverified_numbers.md`, one line each, in the form "- cell `<table>:<row>:<col>`, p. <page>" or "- table `<table>`, p. <page>". They stay out of the arithmetic, and the output lists them as not verified.
   - At levels where the `numbers` stop is not asked (light, auto; see `stops_for` in `plumb/checkin.py`), take the recommended option for every question in both rounds (A, or C for a star flag that numeric fidelity rated benign) and record it the same way with `--note auto` (a skipped stop's answer is never an override). Disagreeing cells and tables then stay out of the arithmetic and go to `unverified_numbers.md`, and every arithmetic and text-table flag is kept, except a star flag answered C.
6. Reference list. Run `python3 {PLUGIN}/skills/review/scripts/check_reference_list.py <pdf> {WORKSPACE}/stage-1/reference_list.md <config contact_email>`. It finds the paper's reference section, looks up each entry, and writes whether each cited work exists with matching authors and year. It is not a gate, and it runs at every depth. On exit 0 or 1, log `plumb log {WORKSPACE} verification '{"check":"reference_list","exit":<code>,"report":"stage-1/reference_list.md"}'`. Exit 1 means some works were not found or their authors do not match; those are findings about the paper. Exit 2 means the lookups could not run or no reference section was found: log `plumb log {WORKSPACE} dependency '{"name":"reference_list","message":"reference list not checked; see stage-1/reference_list.md"}'` and continue.
   On exit 1, add one record to `{WORKSPACE}/stage-1/flags.json` for each entry the report lists as not found, not matching, or not looked up: `item` `ref:<k>` (k = the entry's number in the report), `kind` `reference`, `title`, `summary` (what the lookup found, in one plain sentence), `excerpt` (the entry as the paper prints it, word for word), `ms_page` and `pdf_page` null, and `lookup_failed` (true when the lookups could not reach any database for that entry; otherwise false).

Resume. If this stage runs again after a stopped run, `compare_transcriptions.py` rewrites the agreed tables with the disagreeing cells blanked, and `verify_arithmetic.py` rewrites the flags. The answered questions are not asked again, so replay them. Read the recorded answers with `plumb answered {WORKSPACE} --labels` (the last answer for each item wins; the same answers are the `checkin` events in `{WORKSPACE}/audit/events.jsonl`). After step 1, for each `numbers:cell:*` answer B, C, or D, write the value after the colon in its label into the agreed table; for each `numbers:table:*` answer B or C, copy that CSV into `{WORKSPACE}/extracted_tables/`. Then run step 2. Replay `numbers:hyp:mapping` first: when its recorded answer is B, dispatch `agents/hypothesis-ledger-checker.md` with its recorded note and rerun the gate and the script as in step 3. In round 2, drop again each `numbers:arith:*`, `numbers:text:*`, or `numbers:pack:*` flag answered B, and each `stars_vs_se` flag answered C. Drop again each `numbers:hyp:*` flag answered B as well. Build `unverified_numbers.md` from the cells and tables whose recorded answer is A, `dropped_flags.md` from the round 2 items answered B or C (never `numbers:hyp:mapping`, which is not a flag), and `flags.json` as in step 5. Ask only the questions that have no recorded answer.

Quote and citation checks on the tool's own draft run in Stage 6, once a draft exists.
