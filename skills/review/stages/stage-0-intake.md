# Stage 0: Intake

Nothing from the manuscript enters this conversation, and no agent reads it, before the consent check in step 7 passes and the user starts the review at the recap in step 8. Anything you read or print in this conversation goes to the model provider, so until then do not open the PDF, print or quote its text, view its page images, or run any command on it, for any reason, including to look into a warning. Steps 1 and 4-8 never read the PDF's contents. A referee at a journal that bars AI tools is stopped at step 6, before anything has read the paper. The PDF checks run at the start of step 9, and the models and limits step 9 uses are set at the end of step 5.

1. When Resume in SKILL.md found no unfinished run, or the user chose "Start over", create the run folder: `plumb run-dir new <pdf> --cwd <project dir>`, adding `--fresh` after "Start over" (the new run then never resumes the unfinished one, and its `run.json` names the run left as it was) and leaving out `--cwd` where there is no project directory (see your platform reference). It prints `root`, `run_dir`, and `workspace`. Set `{RUN}` to `run_dir` and `{WORKSPACE}` to `workspace`. After "Start over", record the answer in the new run: `plumb checkin {WORKSPACE} setup setup:resume "A. Continue from where the last run stopped (Recommended)" "B. Start over" --note preference`. Then run `plumb usage mark {WORKSPACE} --cwd <project dir>`, again leaving out `--cwd` where there is no project directory. From then on, where the platform runs plugin hooks, a hook notes where each agent's transcript is, and Stage 7 totals the tokens and time. The root is the project directory when the PDF is inside it and it is not the home folder, Desktop, Downloads, Documents, or the top of Dropbox or iCloud Drive; otherwise it is a new folder named after the paper, next to the PDF. The run folder is `<root>/plumb_output/<date>/` (`-2`, `-3` for a second or third run that day), and it starts with a `run.json` holding `pdf_path` and `started`. The PDF is never moved or copied. The search date cap is an evaluation option, never a setup question: only when the user's request or the prompt of a scripted evaluation run gives a cap (for example "search cap 2022-02-23"), add `--search-before <date>` (YYYY-MM-DD) to `plumb run-dir new`, which writes `search_before` into `run.json` for the research agents and the citation script to read. A cap already in `run.json` stays as it is. When a resumed run reruns Stage 0, `{RUN}` and `{WORKSPACE}` are already set: skip `plumb run-dir new`. Run `plumb deps`. If `missing_required` is not empty, stop and tell the user to run `/plumb:setup`. If `codex` is false and the config asks for Codex, log a dependency warning.
2. The text check runs at the start of step 9, after the consent check and the recap. Do not run it now.
3. Table pages are rendered at the start of step 9 too. Do not render them now.
4. Load packs: `plumb validate-packs {PLUGIN}/packs`. It prints `{"packs": {<name>: <status>}, "overlays": [<names>], "cues": {<overlay>: [<cues>]}}`. The names under `packs` are the built packs, `overlays` names those that run alongside any paper type, and `cues` gives each overlay's detection cues; keep all three, with each pack's status, for steps 10, 11, and 13. It also prints `"modules"`: each pack's design modules with their labels, definitions, and cues; keep it for step 10. If it exits 1, show its message and stop. Step 13 logs the packs whose fixture is pending.
