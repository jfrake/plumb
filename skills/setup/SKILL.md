---
name: setup
description: "Set up Plumb. Checks what is installed, offers optional pieces, and saves your settings. Use when the user installs Plumb or a review reports missing dependencies."
allowed-tools: [Bash, AskUserQuestion, Write]
---

First read the platform reference in the review skill (`../review/references/<platform>.md`) and use its ASK and RUN actions below. On Codex, `${CLAUDE_PLUGIN_ROOT}` is the path in `~/.config/plumb/plugin_root`.

1. Run `PYTHONPATH="${CLAUDE_PLUGIN_ROOT}" python3 -m plumb deps`.
2. If `missing_required` lists packages, show the one command to fix it: `python3 -m pip install --user <packages>`, writing `pymupdf` as `"pymupdf>=1.24.3"`. ASK: "A. Run it for me (Recommended)" or "B. I'll run it myself". Run it only on A. Then re-check.
   If pip refuses with `externally-managed-environment` (a Python that PEP 668 protects), offer a virtual environment instead: `python3 -m venv ~/.config/plumb/venv && ~/.config/plumb/venv/bin/python -m pip install <packages>`. The review skill calls `python3`, so tell the user to run `source ~/.config/plumb/venv/bin/activate` in the shell they start Claude Code or Codex from, then start a new session and run setup again. This works only for sessions started from that terminal; the desktop app and IDE launches do not read it, so for those the packages must be installed for the `python3` they find.
3. Ask for an email address for the free citation-lookup services (OpenAlex, Crossref ask for one). Say it is optional and stored only on this computer. Also tell the user, without asking for it, that an optional free OpenAlex API key raises the daily lookup budget for the citation gap lists, and that they can set it themselves as the environment variable `OPENALEX_API_KEY` or as `openalex_api_key` in the Plumb config file. Setup keeps a saved key when it rewrites the config, so a key saved in the file can only be cleared by editing the config file.
4. If `codex` is on PATH, ask whether to use Codex for the optional stress test at Standard and Deep depth. Say that it sends the paper's text and the draft's points to OpenAI, and that each Standard or Deep run's consent screen asks about OpenAI's training and retention settings. Otherwise say that Codex is optional, that without it a fresh Claude agent runs the stress test, and skip.
5. Ask how you use Claude: "API account", "Claude plan with training turned off", "Claude plan, not sure". If "not sure", explain that consumer plans may use chats for training unless it is turned off at claude.ai/settings/data-privacy-controls. Say the consent check at each run will ask again.
6. Ask which models to use. On Claude Code and the Claude desktop app: "A. A mid-tier model for mechanical work and the top model for judgment (Recommended)" writes `{"mechanical": "sonnet", "judgment": "opus"}`, the tier aliases the Task tool accepts (they follow the newest model in each tier, so nothing is pinned); "B. The session's model for everything" writes `{"mechanical": "inherit", "judgment": "inherit"}`. On Codex, write `inherit` for both. Say that Deep depth uses the judgment model for every agent.
7. Write the settings with `PYTHONPATH="${CLAUDE_PLUGIN_ROOT}" python3 -c "from plumb import config; config.save(config.Config(contact_email='<email>', codex_enabled=<True|False>, models=<models from step 6>))"`. Show where the file was saved.
